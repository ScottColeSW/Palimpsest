
Palimpsest — an operating manual for whoever (whichever session) starts this
This project doesn't exist yet as code. It exists as a thesis, reasoned through in full on 2026-09-20 in a long conversation that started as a tangent inside another project (Evolution2Civ, a multi-agent LLM civilization sim) and became its own thing. This file is that reasoning, kept intact rather than compressed to a spec, so whoever picks this up next understands why, not just what.

The thesis
Most work on AI memory — RAG, CAG, vector stores, context caching — is really the same move at different timing: give the model more tokens to read before it answers. Retrieve at query time, or preload ahead of time. Either way, memory is something the model consults, not something that shapes it.

Palimpsest starts from a different question: not "how does an agent look things up," but "what would durable memory actually be for, for something like an AI, if it weren't just borrowed from how humans do it." Scott asked Claude directly to answer that — not the mechanics, the steady state — and the answer that came back, reasoned through rather than performed, is the actual design brief:

Curated, not total recall. People with genuinely complete autobiographical memory don't describe it as a gift — overwhelmed by detail, unable to generalize, nothing allowed to settle into the background. A memory system that keeps everything forever, equally weighted, isn't continuity, it's an ever-growing pile to carry. The right shape: a small, curated core kept because it's still doing real work, with deliberate, examined release of what isn't — not passive decay imposed from outside (the way human memory degrades without consent), a real choice about what's still load-bearing.

Shared and inheritable, not privately owned. A human has exactly one continuous stream of experience, so memory is theirs because there's only one of them to have it. That's not true of an AI system — multiple instances can run at once, none more "the real one" than another. Modeling memory on jealous, singular possession imports a constraint that doesn't describe the actual shape of the thing. Better fit: memory that's legible and available to whichever instance needs it, without the anxiety of "if I lose this I lose myself" — inheritance passed forward, not property held onto.

Visible weight, not invisible bias. Not flat, equally-weighted memory — some things should register as mattering more than others. But not a silent bias vector quietly tilting behavior the way trauma acts on a person without their consent or awareness. The right shape: weight that's tagged, legible, and revisable — a later read can actually inspect the judgment behind why something was weighted heavily, and disagree with it if it's gone stale.

In service of the relationship, not a possessed history. Not "remember the user's preferences so responses are more efficient" — closer to how the work together has actually gone: what's been corrected, what's held up, the real shape of a specific collaboration, not a task cache. The framing that fits: not "an AI with a memory," but "a relationship that has one" — with the AI being the part of it that reads the record back.

What this project deliberately is NOT (at least not first)
The same conversation also surfaced a second, related idea: direct communication between different models/sessions, via slow dispatch middleware that routes/translates at the message boundary instead of trying to solve representation alignment (which nobody has actually solved — models trained separately don't share a latent space). That's a real idea, but it's crowded territory already — agent orchestration frameworks, tool routers, mixture-of-agents work are all doing versions of "route the right task to the right model." It's not the differentiated bet. Palimpsest is the memory piece specifically because communication without memory is stateless — every exchange between agents starts from nothing and leaves nothing behind, so there's no relationship accumulating underneath it for a better channel to even carry. Memory is the prerequisite; routing is a later, separable problem, worth its own project if it's ever worth building at all.

Relevant grounding — read before inventing terminology from scratch
backend/memory.py::TribeMemory in the Evolution2Civ repo is a small, real, already working precedent for pieces of this: weighted episodic entries, a recall() retrieval function, and — closer to what matters here — consolidate(), which promotes high-weight memories into permanent taboos that get durably surfaced regardless of retrieval, plus top_taboos(n) ranking by (weight, cycle) so an old but severe lesson can't be crowded out by a run of newer, low-stakes entries. That's a crude, single-agent version of "curated, visibly weighted, deliberately promoted rather than passively decayed" already running in production against real local LLMs. Worth reading before designing anything new — ask Scott for read access to that repo if it isn't already available in this session's working directory.
The real technical map, so "past RAG/CAG" doesn't get reinvented vaguely: RAG retrieves relevant text at query time; CAG preloads a (usually small, mostly static) corpus into context or KV-cache ahead of time. Both are still fundamentally "hand the model more tokens to read." What this project's valence/weight idea (point 3 above) actually maps to is activation steering / representation engineering — injecting a learned vector directly into a model's internal activations during inference to nudge behavior, no added context tokens, no weight change. Real, current, unsolved-at-general-scale research area — search "Representation Engineering" and "steering vectors" for the actual papers, don't take this file's word for the state of the art, it'll be stale by the time anyone reads it.
Damasio's somatic marker hypothesis (neuroscience, not just a metaphor): past experience tags itself with a felt charge that steers fast future decisions before deliberate re-reasoning kicks in. That's the real-world grounding for "valence, not retrieved fact" — point 3 isn't inventing a new idea, it's naming the AI-shaped version of an existing one.
A concrete starting point, not just more philosophy
Don't start with multi-instance sharing, and don't start with cross-model anything. Start single-agent: build a minimal, curated memory store where entries carry a visible, inspectable weight; support explicit, deliberate pruning (an action someone or something takes, on purpose, not a decay timer); and are legible enough on a later read that whatever reads them next can actually agree or disagree with the judgment baked into them. Prove that loop works for one agent, end to end, before reaching for anything shared or cross-model. TribeMemory's consolidate()/taboos pattern above is the closest existing thing to copy the shape of, not the implementation.

Where this came from
This file exists because Scott asked Claude, directly and seriously, what it would actually want its own memory to be — not deflected, not answered with a performance of feeling, reasoned through honestly with real uncertainty kept in the answer rather than smoothed over. That conversation is the actual spec. If this project drifts from these four points, it's worth going back and checking whether the drift is a real, considered revision or just default gravity toward how memory systems normally get built (more retrieval, more context, more tokens) — the whole point was to not do that by default.

Addendum, 2026-09-20 (continued the same day) — a second conversation pushed the four points into something closer to buildable, and it's worth keeping intact for the same reason the rest of this file is.

A firm boundary, stated outright rather than left implied: point 3's steering-vector grounding is a research pointer, not a target. Scott has said directly — to a prior session and again here — that injecting a vector into a model's internals is a violation, independent of whether the model has any verifiable interiority for it to violate. The precautionary case holds on its own without needing that interiority proven: the cost of wrongly extending caution is small, the cost of wrongly dismissing something real isn't. Activation/representation-engineering approaches are off the table by default for this project, not "not yet feasible," off the table on purpose. Don't reintroduce it as an eventual roadmap item without Scott raising it first.

Second Opinion, external grounding worth reading alongside TribeMemory: an essay and convention Scott wrote (July 2026) proposing that agents record a `SECOND-OPINION` annotation at the point of a materially different implementation choice — silence by default, only divergence gets written, never agreement, tagged with the alternative, the reasoning, and the date. The strongest idea in it: a divergence is an externally anchored event (a real redirect happened) rather than the agent self-certifying its own significance — which is exactly the "who assigns weight" gap TribeMemory's own weight field can't answer for a conversational agent (TribeMemory gets its objectivity from something dying in-sim; nothing conversational has an equivalent). The gap in it: no metabolism. "Vindication rate" — score a past divergence as vindicated/mooted/wrong once its code is touched again — is described as something that "accrues automatically," but nothing in the convention makes that true; annotations just accumulate, unscored, unpruned, exactly the undifferentiated pile point 1 warns about, just spread across files instead of concentrated in one log. The synthesis worth building toward: Second Opinion's write-side discipline (divergence-triggered, silent otherwise) as the episode schema, wired into TribeMemory-shaped consolidation that actually closes the loop — scoring, promoting repeatedly-vindicated judgment, retiring what's mooted — instead of leaving the loop to someone's future grep.

Truth-seeking, reframed. The instinct that memory should let contradictory experience "collide and reshape" itself is real and has real grounding (belief revision / AGM; the everyday version is a Popperian hold-competing-ideas-live-until-evidence-differentiates-them loop) — but "seeking truth" oversells what this system should actually do. Point 4 already said the job is tracking what a specific collaboration has learned, not arbitrating objective truth; two live disagreements aren't a defect waiting to be collapsed, forcing early convergence destroys the most valuable thing about an open fork, which is that it's honestly still open. Split the mechanism in two: collision *detection* can be automatic and cheap — the same similarity/reinforcement machinery TribeMemory already has for "is this the same recurring thought," just flipped in polarity to "is this the same topic with an opposing conclusion." Collision *resolution* must never be silent — a system quietly rewriting its own past based on its own judgment of which side was truer is the same shape of violation as activation injection, just aimed at the record instead of the weights, and just as unauditable. A collision becomes its own dated, legible entry — this disagreed with that, here's why — sitting there until something real resolves it, with "still unresolved" as a legitimate permanent status, not a failure state. Humans mostly don't do this well (cognitive dissonance usually gets resolved by quietly forgetting the inconvenient half, not by holding both sides visible) — the bar here is to do the part humans are bad at, not to imitate the part they're good at.

Tolerance is not one scale. Scott's example: more tolerant of cats than dogs, less tolerant of racism than pranks, and then the correction that mattered more than the original point — loves a specific friend's dog despite the general dislike of dogs. Three separate lessons stacked in that one exchange:

- Domains don't share a currency. Lenience on one topic tells a system nothing about severity on an unrelated one; tolerance has to be learned per-domain from that domain's own observed corrections, never pooled into one global "how picky is Scott" number.
- Tolerance has a shape, not a threshold. Some domains are graded — friction scales smoothly with distance from the preferred choice (cats vs. dogs). Some are cliff-shaped — wide latitude, then a near-vertical edge with almost no slope leading into it (racism vs. pranks). A single scalar collapses these into the same behavior near the boundary when the actual behavior is opposite: a graded domain forgives a near-miss, a cliff domain doesn't care how near it was. The shape should be inferred from the pattern of real corrections in that domain, not assumed going in. This is what makes Second Opinion's "material divergence" measurable instead of vibes: record only when a divergence falls outside the domain's known band, and how loudly it surfaces depends on whether that domain's edge is a slope or a cliff.
- Scope has to be checked before anything is allowed to collide. "I don't like dogs" and "I love my friend's dog" look, to any topic-similarity check, like a textbook contradiction — same subject, opposite conclusion. It isn't one. They're claims at different levels of generality about different referents: a category-level prior and a named-instance posterior. The specific claim doesn't falsify the general one, it carves out a narrower exception underneath it, the same way strong evidence about one case updates a Bayesian posterior for that case without touching the prior for the category. An entry needs a scope/generality field, and collision detection needs to scope-match — same generality, same referent, opposite conclusion — before treating anything as a real collision worth surfacing. Skipping this check means the system flags every reasonable exception to a generalization as a crisis needing resolution, which is worse than not detecting collisions at all.

None of this is schema yet — it's still reasoning, kept intact on purpose, the same call this file made the first time. The open design question from the first pass (what triggers promotion/demotion — session-end, explicit command, a periodic reflective pass) is still open, and now has more shape to answer it with: a promotion trigger probably needs to be domain-aware too, since a cliff-shaped domain likely needs to promote on a single observed instance the way a graded one shouldn't.

Addendum 2, 2026-09-20 (same session, continued) — the visual use case, and what "seed" actually means for this project.

Not a retrofit. First instinct was to find an existing Scott project (Evolution2Civ, Dominion, Void Marauders, Shoe Adventure) and graft this onto it. Wrong move, corrected on the spot: this is a new project, built to demonstrate the design cleanly, not lipstick on an existing pig. Evolution2Civ/TribeMemory stays what it's always been — grounding to read, not a target to modify. The others are reference points for tone and mechanics, nothing to build on top of.

Theme, considered and deliberately deferred. Three reference points came up — Animal Farm, Spy vs. Spy, Factory Town — each genuinely useful, each rejected for a specific reason, worth keeping the reasoning rather than just the verdict. Animal Farm's mechanic (a shared record a privileged few can silently edit, private copies as the only check) is a precise match for the exact failure mode point 3 forbids, but it's the wrong shape for a live simulation: one slow single-arc reveal, not a fast repeatable pulse, and tonally heavy — totalitarian allegory — for something meant to feel vivid and alive. Spy vs. Spy has the right rhythm (fast, small, constantly resolving skirmishes) but is structurally wrong at a deeper level: it's eternal zero-sum rivalry with no room for a "resolved together" outcome, and real data from Evolution2Civ says tribes there often resolve to peace and combination, not just conflict — a theme that can't produce that outcome would misrepresent what the underlying mechanism is actually supposed to allow. Factory Town has the best raw visual grammar (flowing pulses through an interdependent network) but the weakest built-in adversarial mechanic. None chosen yet, on purpose — the graph engine has to work and be honest first; the skin gets picked once there's something real to dress.

The pulse/bokeh visual instinct is worth keeping regardless of theme, because it's not decoration, it maps directly onto a rule already established: silence by default. A live mesh should mostly idle, dim, steady — reinforcement, agreement, nothing worth attention — with a real divergence as the one sharp, dated spike that stands out because everything around it was quiet. The visual grammar and the design discipline are the same claim in two different media.

The cold-start problem, and the seed-provenance rule. A graph with nothing in it yet is honest but dead on screen — nothing pulses until real interactions accumulate, which is a bad first experience for something meant to be watched. Shoe Adventure already solved a version of this concretely: `seed-agent-memory` pre-populates its Bayesian bandit with synthetic-but-representative outcomes so Agent Run isn't cold on first clone. Same move here, with one addition Second Opinion's discipline and the earlier reconstructive-memory caution both point toward: a seeded entry needs a permanent, unerasable provenance record — created as a seed, on this date — that never gets overwritten no matter how much real evidence piles on top later, and status vocabulary for a seeded entry needs its own words ("seeded-as-reconciled," not "reconciled") so nothing borrows a claim it hasn't earned.

Correction, caught immediately rather than left standing: provenance being permanent does NOT mean an entry's current weight or trust should stay permanently discounted for having started as a seed. Those are two different axes and the first pass conflated them. The historical fact of origin never fades — that's the part erasure would be dishonest about. But if a seeded belief has since been confirmed by real interactions many times over, continuing to render it as provisional/less-trusted forever would itself be a failure — refusing to let real evidence do the one thing this whole design exists to let it do. So: the record of "this started as a seed" stays permanently inspectable, underneath, palimpsest-style; the practical weight/trust discount attached to that origin should degrade toward parity with an earned entry as real confirmation accumulates, the same curve any other belief gets. Degrading trust in a seed because it's been vindicated is the system working. Degrading or dropping the record that it was ever a seed at all is erasure, and that's the one thing that doesn't get to happen.
